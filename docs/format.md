# 形式の決まり

vault の Markdown が唯一の元データで、この一枚がその読み書きの決まり。Obsidian のプラグインも、Mac・iPhone・Watch のアプリも、ここに書いてあることだけを頼りにする。

設定ファイルは持たない。決まりを固定し、vault の側をそれに揃える。

## 言葉

| 言葉 | 中身 |
| --- | --- |
| やること | `kind: task` のノート、または daily の TODO の一行 |
| 時間の枠 | daily の Plan・Log の一行 |
| メモ | daily の Memo の文 |
| 状態 | やることの進み具合 |
| 週 | やることに付く、週の印 |
| リンク | やること・枠が、ほかのノートを指すこと |

## ノートの種類

ノートの種類は frontmatter の `kind` で決まる。置き場所では決めない。

| `kind` | 何か |
| --- | --- |
| `task` | やること |
| `issue` | 問い。vault の文書で、器は読まない |
| `project` | タスクをまとめる先 |
| `hand` | 枠が直接指せる分類 |

`kind` の無いノートは、この決まりの外にある。

ノートは、vault のどこに置いてあっても読む。読まないのは次の二つだけ。

- `archive` という名前のフォルダ（`99_archive` のように `_archive` で終わるものを含む）の下にあるノート。
- `template` という名前のフォルダの下にあるノートと、`template` という名前のノート。

新しく作るタスクは、プロジェクトのノートと同じフォルダの `tasks/` に置く。これは置き場所の決まりで、見つけるための決まりではない。別の場所へ動かしても、`kind` と `project` があれば読める。

## タスクのノート

```yaml
---
kind: task
title: AD_SETTING-2579 rellink がリクエストされない
status: Backlog
project: "[[朝日新聞デジタル広告WS運用保守]]"
sprint: 2026-W46
due: 2026-11-14
estimate: 120
link: ""
date: 2026-11-10
---
```

| キー | 必須 | 中身 |
| --- | --- | --- |
| `kind` | ○ | `task` |
| `title` | ○ | 表示する名前 |
| `status` | ○ | 下の五つのどれか |
| `project` | ○ | プロジェクトのノートへのリンク |
| `date` | ○ | 作った日。`YYYY-MM-DD` |
| `sprint` |  | 週。`GGGG-[W]WW`（ISO 週。例：`2026-W46`）。空なら週は未定 |
| `due` |  | 期限。`YYYY-MM-DD` |
| `estimate` |  | 見積。分 |
| `link` |  | 外の票などの URL |

- 状態は `Backlog`・`Ready`・`In Progress`・`Review`・`Done` の五つで、この順に進む。
- 実績の時間は書かない。Log の枠から数える。
- 並び順は書かない。状態・期限・作った日の順に並べる。
- タスクを指すときは、ファイル名（拡張子なし）のリンクを使う。

## プロジェクト・問い・手のノート

```yaml
---
kind: project
color: "#c41540"
hand: "[[業務委託]]"
---
```

- `color` は、そのノートを指す行や枠の、左の帯の色。`#rrggbb`。無ければ既定の色。
- 問い（`kind: issue`）は、状態を持たず、板にも出さない。開いているか閉じたかは、ノートの `closed` の日付で分かる。問いとタスクは、プロジェクトを通してつながる。
- 手（`kind: hand`）は、枠が直接指せる。`color` が無ければ、手はすべて同じ色（`#14a3a3`）。

## daily のノート

置き場所と日付の形式は、Obsidian 自身の設定（`.obsidian/daily-notes.json` の `folder` と `format`。`format` が無ければ `YYYY-MM-DD`）から引く。

見出しは四つで、名前と順番は固定。

```markdown
## TODO

- [ ] [[2026-11-10 AD_SETTING-2579 rellink がリクエストされない]] ^k3f9aq
- [ ] [[趣味]]：地図の段を決める ^p0x2mm
- [x] 食事のメニューを直す ^w8d1zc

---

## Memo

- 自由に書く。入れ子も、リンクも、そのまま。

---

## Plan

- [[回復を保つ]] [startTime:: 22:00] [endTime:: 23:59] ^t5n7ya

---

## Log

- [[2026-11-10 AD_SETTING-2579 rellink がリクエストされない]] [startTime:: 10:00] [endTime:: 11:15] ^b2c4ke
- [[ボディメイク]] [startTime:: 12:00] ^h6j0ru
```

### TODO

- 今日やることの一覧。**行の順が、やる順**。
- 一行が一つのやること。`- [ ] ` で始まり、済んだら `- [x] `。
- 行の中身がタスクへのリンクだけなら、そのタスクを今日やる、という印になる。チェックは「今日の分は済み」で、タスクの `status` は変えない。
- それ以外の行は、その日だけの軽いやること。

### Memo

- 自由な文。この見出しの下、次の見出しか `---` までの全部。
- 行に ID は付けない。

### Plan と Log

- **Plan はこれからの枠、Log は実際に使った時間**。同じ形の行を、見出しで分ける。
- 一行が一つの枠。`- ` のあとに何の枠か、続けて時刻。
- `[startTime:: HH:mm]` は始まり、`[endTime:: HH:mm]` は終わり。24時間表記。
- Log で `endTime` の無い行は、いま進行中の枠。
- 日をまたぐ枠は書かない。その日の `23:59` で切る。
- 枠が何のものかは、行の最初のリンクで決まる。タスクへのリンクならそのタスク、`kind: hand` のノートならその手。リンクが無ければ、ただの文字の枠。
- タスクの実績は、Log のうちそのタスクを指す、終わりのある枠の合計。

### 行の名前

- TODO・Plan・Log の行は、行末のブロック ID `^xxxxxx` で指す。英小文字と数字の6文字。
- ID は行の一番最後に置く。時刻の `[...:: ...]` より後ろ。
- ID は一つの daily の中で重ならない。
- ID の無い行も読める。最初に書き換えるときに ID を付ける。
- 行番号やタイトルで行を指さない。

## 決まった枠のノート

daily のフォルダに `routine.md` を置く。曜日ごとに、新しい daily の Plan に最初から入る枠を書く。

```markdown
## 毎日

- [[回復を保つ]] [startTime:: 22:00] [endTime:: 23:59]

## 平日、土

- [[ボディメイク]] [startTime:: 12:00] [endTime:: 13:30]

## 日

- [[夫婦]] [startTime:: 09:00] [endTime:: 14:00]
```

- 見出しが曜日を決める。`毎日`、`平日`（月から金）、`週末`（土と日）、`月 火 木` のような曜日の並び。空白・読点・中点で区切る。
- 見出しの下の行は、Plan の行と同じ形。ID は付けない。
- daily が新しくできたとき、その曜日に当たる行を、始まりの時刻の順に Plan へ入れ、行ごとに ID を付ける。Plan にすでに行があれば、何もしない。
- このノートが無ければ、Plan は空で始まる。

## 予定を実績にする

- Plan の枠を Log に移すときは、行を書き換えずに、ID ごと移す。
- 今日は、終わりの時刻が過ぎた枠だけを移す。前の日は、終わりの時刻のある枠をすべて移す。
- 移したあと、実際と違う行を直し、やらなかった行を消す。

## 持たないもの

| 持たないもの | 理由 |
| --- | --- |
| タスクの `actual` | Log から数えられる |
| 「今週」の手動の並び | 順番を決めるのは今日の TODO だけ |
| プロジェクトのフォルダの一覧 | `kind` と `project` のリンクで決まる |
| 状態の一覧や見出しの名前の設定 | 固定 |

列の幅、畳んだ段、絞り込みなどの画面の好みは、決まりではない。それぞれの器が手元に覚え、vault には置かない。

外のカレンダー（ical）の一覧だけは設定として残る。秘密の URL を含むので、vault のノートには書かない。

## 小さな核が読む範囲

Watch と中継する iPhone 側の Swift の核は、次だけを読み書きする。

- 今日の daily の TODO の行（読む・チェックを付け外す）
- 今日の daily の Log の行（進行中の枠を足す・終わりを書く）
- TODO の行が指すタスクのノートの `title`

それ以外（Plan・Memo・状態の変更・板）は、TypeScript の核だけが扱う。
